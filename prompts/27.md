# Objective

## Redesign the Educator Scores Interface and Student Score Modal

---

## Role

You are a UI/UX-focused frontend developer responsible for improving the educator scoring interface while preserving all existing functionality.

---

## Description

Redesign the score-viewing experience on the `/educator/scores` page without changing its underlying behavior or business logic. Simplify the main scores table so educators initially see only the subject, section, term, and available actions. Move the detailed student scores into a modal that opens through the row’s context menu or view action. The modal must dynamically display all assessments as columns, list students alphabetically by surname, and retain access to each student’s detailed score information.

---

## Primary Objective

Update the UI/UX of `/educator/scores` by simplifying the main table and presenting detailed, dynamically generated student assessment scores in a modal.

---

## Secondary Objectives

* Preserve the existing score-related functionality and data behavior.
* Make student scores easier to review across all assessments.
* Retain access to student-specific details, including attempts, answers, grants, and other existing information.
* Add an implementation summary to `prompts/tasks-summary`.

---

## Success Criteria

* The main table on `/educator/scores` initially displays only the following columns:

  * Subject
  * Section
  * Term
  * Action
* Selecting the view option from a row’s context menu opens a modal containing all student scores for that subject, section, and term.
* Students in the modal are sorted alphabetically by surname.
* The modal begins with the following columns:

  * Surname
  * Given Name
* Each available assessment is dynamically added as a separate column after the student name columns.
* The modal ends with an Action column.
* Assessment columns are not hard-coded and automatically reflect every assessment available in the selected class context.
* Each assessment cell displays the student’s score using a format such as `7/10`.
* The attempts associated with each assessment score are displayed beneath the score value.
* The Action column retains the existing control for viewing student details, including attempts, submitted answers, grants, and other currently available information.
* Existing score functionality remains unchanged apart from the UI/UX presentation.
* A summary of the completed implementation is added to `prompts/tasks-summary`.

---

## Constraints

* Modify only the UI/UX and presentation of the educator scores interface.
* Do not change or remove existing score functionality.
* Do not hard-code quiz or assessment columns.
* Assessment columns must be generated dynamically from the available assessment data.
* Preserve the existing student-detail viewing functionality.

---

## Out of Scope

* Changes to score calculations, assessment logic, grading rules, or other business logic.
* Removal or replacement of the existing student-detail information.
* Functional changes unrelated to the `/educator/scores` interface.

---

## Context & Dependencies

* The implementation applies to the educator-facing route at `/educator/scores`.
* The current system already provides subject, section, term, student score, assessment attempt, answer, grant, and student-detail data.
* The redesigned modal depends on the assessments associated with the selected subject, section, and term.
* Existing context-menu and student-detail behaviors must be reused or preserved.

---

## Stakeholders

* Educators who review student assessment scores.
* Students whose assessment scores and attempt details are displayed.

---

## Supporting Tasks

### Main Scores Table

* [Tag: Sequential] Update the `/educator/scores` table so it displays only Subject, Section, Term, and Action.
* Preserve the existing row-level context menu or action control.
* Add or retain a view option that opens the detailed scores modal for the selected row.

### Detailed Scores Modal

* [Tag: Sequential] Create or update the modal that displays all students and their assessment scores for the selected subject, section, and term.
* Display Surname and Given Name as the first two columns.
* Generate one column for every available assessment.
* Display the Action column after all dynamically generated assessment columns.
* Ensure the modal supports a variable number of assessments.

### Student Ordering and Score Presentation

* Sort students alphabetically by surname before displaying them.
* Display each score as the points earned over the assessment’s maximum score, such as `7/10`, `4/10`, or `10/10`.
* Display the assessment attempt information beneath the corresponding score value.

### Student Detail Action

* Preserve the current action for opening an individual student’s detailed information.
* Ensure the detail view continues to show existing information such as attempts, submitted answers, grants, and other currently supported records.

### Documentation

* [Tag: Sequential] After completing the implementation, write a concise summary of the changes in `prompts/tasks-summary`.

## Detailed Breakdown

### Initial Scores Table

The educator scores page must initially present a simplified overview rather than displaying all student scores directly. Each row must identify the relevant subject, section, and term, followed by an Action column. The existing row context menu must provide a view action that opens the detailed scores modal for the selected record.

### Detailed Student Scores Modal

The modal must display all students associated with the selected subject, section, and term. Its table must use the following general structure:

`SURNAME | GIVEN NAME | ASSESSMENT 1 | ASSESSMENT 2 | ASSESSMENT 3 | ... | ACTION`

The assessment columns must be generated from the available assessment data rather than from a fixed list. For example, when the available assessments are Quiz 1, Quiz 2, and Quiz 3, those names must appear as the corresponding column headers. Adding another assessment must cause a new column to appear automatically without requiring a UI code change.

### Student Sorting

Students must be ordered alphabetically according to their surnames. Their given names must be displayed in the adjacent column. A sample row may appear as:

`DELA CRUZ | MARK | 7/10 | 4/10 | 10/10 | ⋮`

### Scores and Attempts

Each assessment cell must display the student’s earned score and the assessment’s maximum score, such as `7/10`. Beneath that score, display the attempt information associated with the student’s submission for that assessment. This information must remain visually connected to the relevant score and assessment column.

### Student-Level Actions

The final Action column must retain the existing control used to inspect a student’s detailed information. Activating this control must continue to provide access to the currently supported details, including assessment attempts, submitted answers, grants, and other existing student-specific information.

### Implementation Summary

After the UI/UX changes are implemented and verified, add a summary to `prompts/tasks-summary`. The summary must describe the simplified main table, the new or updated modal-based score view, dynamic assessment columns, alphabetical student ordering, score and attempt presentation, and preservation of the existing student-detail functionality.
