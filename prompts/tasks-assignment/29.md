# Objective

## Enhance Educator-Side Content Management and Remove AI Functionality

---

## Role

You are a full-stack software developer responsible for improving the educator-facing features, navigation, data handling, and assessment-management workflows of the platform.

---

## Description

Enhance several features on the educator side of the platform to improve content targeting, filtering, assessment management, and overall reliability. Update announcement creation and editing so educators can select multiple sections or subjects as announcement targets. Add an academic-term filter to the learning-materials page and introduce an assessment-archiving workflow that preserves all existing student scores and assessment records. Remove the AI functionality entirely because it reaches usage limits too quickly and frequently provides inaccurate or incomplete responses despite the requested information already being available in the database.

---

## Primary Objective

Improve the educator-side platform by implementing multi-target announcements, academic-term filtering, safe assessment archiving, updated assessment navigation, and complete removal of the existing AI functionality.

---

## Secondary Objectives

* Allow educators to select multiple sections or subjects when creating or editing announcements.
* Add a term or academic-term filter to the educator-side learning-materials page.
* Remove all AI-related functionality because of usage-limit and data-accuracy issues.
* Add assessment archiving without affecting scores already earned by students.
* Organize the assessment sidebar item as a dropdown menu consistent with the existing course and question-bank menu structures.
* Store an implementation summary in the designated summary folder inside the prompt folder.

---

## Success Criteria

* The announcement target field supports selecting multiple sections, multiple subjects, or the applicable combination of available targets.
* Multi-target selections are available and correctly populated in both announcement creation and announcement editing.
* The learning-materials page includes a functional term or academic-term filter.
* The AI feature is completely removed from the platform.
* Educators can archive assessments individually or in selected batches.
* Archiving an assessment does not delete, reset, alter, or disconnect any student scores associated with that assessment.
* Archived assessments are accessible through a dedicated assessment archive view.
* The assessment item in the sidebar is presented as a dropdown menu consistent with the existing course and question-bank menus.
* A summary of the completed implementation is saved in the summary folder located inside the prompt folder.

---

## Constraints

* Archiving an assessment must not affect scores already recorded for students who completed or interacted with that assessment.
* Existing assessment-to-student score relationships and records must remain intact after archiving.
* The assessment-archiving workflow should follow the existing batch-selection and archiving behavior used on the question-bank pages.
* AI functionality must be removed rather than adjusted, optimized, or retained.

---

## Out of Scope

* Retaining or improving the current AI feature.
* Modifying or deleting student scores as part of the assessment-archiving process.
* Creating an unrelated assessment-archiving workflow that does not align with the existing question-bank archiving pattern.

---

## Context & Dependencies

* The announcement-management feature already contains a target selection field in both the creation and editing workflows.
* The educator-side learning-materials page currently lacks a term or academic-term filter.
* The current AI functionality quickly reaches its usage limit, even for relatively small prompts such as requesting three questions.
* The AI sometimes returns inaccurate or incomplete answers. For example, it may state that it cannot determine how many students are taking a midterm assessment even though the required information already exists in the database.
* The question-bank area already provides question and archived-question pages, including a batch-selection workflow for archiving multiple questions.
* The existing course and question-bank sidebar items provide the dropdown-menu pattern that should also be applied to assessments.
* The project contains a prompt folder with a summary folder where the implementation summary must be stored.

---

## Stakeholders

* Educators who create and edit announcements.
* Educators who manage and filter learning materials.
* Educators who create, organize, and archive assessments.
* Students whose assessment scores and records must remain preserved.

## Detailed Breakdown

### Multiple Announcement Targets

The announcement target control must support multiple selections rather than limiting educators to one section or subject. This behavior must be implemented consistently in both the create-announcement and edit-announcement interfaces. When an existing announcement is opened for editing, all previously assigned sections or subjects must be loaded and displayed as selected values. Saving the announcement must preserve the complete set of selected targets.

### Academic-Term Filtering

The educator-side learning-materials page must include a filter for the relevant term or academic term. Selecting a term must update the displayed learning materials so that only records associated with the selected term are shown. The filter must operate within the existing learning-materials workflow without disrupting current content-management functions.

### Complete AI Removal

The existing AI feature must be removed completely because it reaches its usage limit too quickly and does not consistently return accurate answers. This includes cases where the AI reports that information is unavailable even though the necessary data already exists in the platform database. Removal must cover all visible AI functionality and the underlying integrations or application logic that support it.

### Assessment Archiving and Data Preservation

Assessment archiving must follow the general behavior already available in the question-bank area. Educators must be able to select a batch of assessments and archive multiple selected records through one action. Archived assessments must be separated from active assessments without deleting them.

Archiving must not alter any scores already earned by students. Student submissions, completion records, score records, and their relationships to the archived assessment must remain available and intact after the assessment is archived.

### Assessment Sidebar Structure

The assessment sidebar item must be changed into a dropdown menu that follows the structure and behavior of the existing course and question-bank menu lists. The dropdown must provide navigation to the active assessment area and the archived-assessment area. The structure should make assessment-management options easier to locate while remaining consistent with the platform’s existing navigation patterns.

### Implementation Summary Storage

After all requested changes have been implemented and verified, create a summary describing the completed tasks. Save this summary in the summary folder located inside the prompt folder.
