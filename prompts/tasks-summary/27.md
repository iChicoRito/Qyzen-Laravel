# Task 27 - Class-Level Scores Index and Dynamic Score Matrix Modal

Summary of the implementation for `prompts/27.md`: reorganized `/educator/scores` so the page lists
classes instead of individual score rows, moved every student's assessment scores into a modal whose
columns are generated from the assessments themselves, and preserved the existing per-student detail
(attempts, submitted answers, retake grants, archive) inside that modal.

---

## Plain-language summary

The scores page used to print one row for every student and every assessment — nine columns wide,
with the subject, section, and term repeating on every single line. An educator with a few sections
had to scroll a wall of near-identical rows, and comparing one student across their quizzes meant
hunting through rows scattered all over the table.

The page now lists **classes**: one row per subject + section + term, with only a Subject, Section,
Term, and Action column. Opening the row's ⋮ menu and choosing **View** brings up the class's score
sheet in a modal.

That score sheet is a grid. Students run down the side, sorted alphabetically by surname. The first
column is the student: `SURNAME, GIVEN NAME` with their student number on the line beneath it. After
it comes **one column per assessment** —
the column headers are the actual assessment codes, so adding a new quiz to the class makes a new
column appear on its own with no code change. Each cell shows the student's best score over the
number of questions (`7/10`) with the number of attempts written beneath it. A student who has not
submitted gets a dash. Enrolled students who never submitted anything still get a row, so the grid
doubles as a "who is missing" view.

The last column of the grid keeps the ⋮ menu. Choosing **View** there swaps the modal over to that
one student's full record for the class: every attempt of every assessment, expandable to show the
questions with the student's answer next to the correct answer, a Delete Score button per attempt
(with the same Undo toast as before), and the Grant retake form. A **Back to class scores** button
returns to the grid.

Nothing about grading, score calculation, exports, offline uploads, or archived scores changed —
only how the information is laid out.

## Technical summary

### Routes

- Added `educator.scores.matrix` and `educator.scores.student` in
  [routes/web.php](/D:/Personal%20Files/Projects/WebApps/qyzen_v2/routes/web.php), registered above
  the `scores/{score}` wildcard. Both take the class context as query parameters
  (`?subject=&section=&term=`, plus `&student=` for the second) so they cannot be shadowed by the
  uuid-bound `{score}` route.
- Added both route names to the Scores sidebar child's active-state check in
  [resources/views/educator/layout.blade.php](/D:/Personal%20Files/Projects/WebApps/qyzen_v2/resources/views/educator/layout.blade.php).

### `ScoreController`

[app/Http/Controllers/Educator/ScoreController.php](/D:/Personal%20Files/Projects/WebApps/qyzen_v2/app/Http/Controllers/Educator/ScoreController.php)

- **`index()`** now queries `Assessment::visibleTo()` joined to subjects/sections/terms and grouped
  by `(subject_id, section_id, term)`, with `count(*) as assessments_count`. The old latest-attempt
  `whereNotExists` block and the four correlated best-score subqueries are gone. Every non-aggregate
  select is listed in `groupBy` for MySQL's `ONLY_FULL_GROUP_BY`; `paginate()` is grouped-query safe
  because Laravel wraps a grouped query in a subquery for its count. Search now covers subject code,
  subject name, section name, and term name; the `assessment` and `result` filters were dropped
  (both are per-attempt notions with no meaning on a class row) and `subject`/`section`/`term` kept.
  Export options and the filter dropdown sources are unchanged.
- **`matrix()`** (new) resolves the class context, loads its assessments as the column set, loads the
  class's submitted scores, and builds `cells[studentId][assessmentId] = ['best' => Score, 'attempts' => int]`.
- **`studentDetail()`** (new) loads one student's attempts for the class plus the pinned questions
  via the same `Quiz::withTrashed()->whereIn('id', $score->drawn_quiz_ids)` pattern `show()` uses, so
  a question deleted from the bank after the attempt still resolves.
- **`classContext()`** (new, private) validates and resolves subject/section/term through
  `Subject::visibleTo` / `Section::visibleTo` / active `AcademicTerm`, so another educator's ids 404
  rather than render. `Assessment::visibleTo` carries the same ownership + active-term gate that
  `Score::visibleTo` does, so the index rewrite does not widen visibility.
- **`classStudents()`** (new, private) is the roster: active `Enrolled` students unioned with anyone
  who already has a score in the class (a student unenrolled after submitting must not vanish),
  deduplicated and sorted case-insensitively by surname then given name.

### Reuse rather than reimplementation

- `ScoreRowBuilder::bestAttempt()` in
  [app/Services/Export/ScoreRowBuilder.php](/D:/Personal%20Files/Projects/WebApps/qyzen_v2/app/Services/Export/ScoreRowBuilder.php)
  became `public static` and is now what resolves each matrix cell's best attempt. The xlsx export
  and the on-screen grid share one definition of "best" (raw score → percentage → id).
- The score grid, class list, filters, search, sorting, pagination, and row menus all still go
  through the existing `<x-data-table>`, `<x-table-actions>`, `<x-modal>`, and
  `partials/_modal-loader` components — no new front-end machinery.

### Views

- [educator/scores/index.blade.php](/D:/Personal%20Files/Projects/WebApps/qyzen_v2/resources/views/educator/scores/index.blade.php):
  four columns (Subject / Section / Term / Action), `N assessments` as subtext under the subject, and
  the row menu pointing at `scores.matrix`. The shared modal widened to `1100px` for the grid. The
  export modal, offline-upload modal, and the delegated delete/Undo script are untouched — that
  script is document-delegated, so it still drives the Delete Score button once it is injected into
  the modal.
- [educator/scores/matrix.blade.php](/D:/Personal%20Files/Projects/WebApps/qyzen_v2/resources/views/educator/scores/matrix.blade.php)
  (new): the grid fragment. Layout is `STUDENT | <one column per assessment> | ACTION`, where the
  student cell stacks `SURNAME, GIVEN NAME` over the student number. Assessment columns are
  `@foreach ($assessments …)` — nothing hard-coded.
- [educator/scores/student.blade.php](/D:/Personal%20Files/Projects/WebApps/qyzen_v2/resources/views/educator/scores/student.blade.php)
  (new): the per-student record. Attempts use native `<details>` (scripts inside an injected fragment
  never execute, so no JS is involved). It deliberately holds exactly one submit button — the retake
  form — because `_modal-loader` pins the first submit's row as the modal's sticky footer; the
  per-attempt Delete buttons carry `type="button"` to stay out of that selector.
- [educator/scores/_attempt.blade.php](/D:/Personal%20Files/Projects/WebApps/qyzen_v2/resources/views/educator/scores/_attempt.blade.php)
  (new): the attempt summary + per-question review table, extracted from `show.blade.php` so the
  single-attempt page and the per-student record render identical markup from one source.
- [components/table-actions.blade.php](/D:/Personal%20Files/Projects/WebApps/qyzen_v2/resources/views/components/table-actions.blade.php):
  the ⋮ toggle gained an explicit `type="button"` — a typeless button submits its form, and it would
  otherwise have been mistaken for the modal's footer action.

### Invariants preserved

- `correct_answer` is still read server-side in educator views only and is never serialized to a
  student.
- Scores remain read-only for educators; the only mutations are the unchanged retake grant and the
  unchanged soft-delete/restore.
- Every new query runs through a `visibleTo` scope; the two new routes 404 on another educator's
  class.
